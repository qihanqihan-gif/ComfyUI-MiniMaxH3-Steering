# 用户自定义创作规则

插件把创作规则分成两条清楚的使用路径：

- **创作规则文件直载（轻量）**：按文件原样合并，不处理作用域、依赖和冲突。适合单文件、已自行确认不会互相打架的规则，也适合做 A/B 对照。
- **创作规则组合（智能）**：选择内置规则，或接收直载节点的“结构化规则包”；统一执行作用域、依赖、冲突和互斥组消解，并输出解析清单。

推荐接线：

```text
创作规则文件直载.结构化规则包
  └─> 创作规则组合.外部规则包
       ├─> 已解析创作规则 ─> 提示词导演.创作规则
       └─> 规则解析清单 ─> 提示词导演.规则解析清单
```

如果只想快速载入一个简单规则，也可以把直载节点的“原样规则文本”直接接到提示词导演。不要再把同一个规则同时通过两条路径接入。

## 文件放在哪里

所有规则统一位于 `prompt_modules/`。三个子目录职责固定：

- `builtin/`：插件正式内置规则，会随插件更新。
- `legacy/`：旧英文规则兼容层，只读，不添加新规则。
- `user/`：个人规则库，内容默认被 Git 忽略。

个人规则建议放入：

```text
prompt_modules/user/
└── 我的规则/
    ├── 固定机位.json
    └── 人物身份保持补充.json
```

文件名可以直接使用中文；节点的文件直载下拉会显示真实相对路径。JSON 内的 `id` 应使用稳定、唯一的小写英文与下划线。改文件内容后下次排队会重新读取；新增、删除或改名后刷新节点定义，必要时重启 ComfyUI。

已有工作流中的英文文件选择会自动映射到 `prompt_modules/builtin/` 的中文正式文件。覆盖升级后若插件根目录仍残留旧 `modules/` 或 `extra_module_roots/`，加载器会继续只读扫描以便迁移；新规则只写入 `prompt_modules/user/`。

## 从简单模板开始

复制 `templates/用户简单创作规则模板.example.json`，修改：

- `id`：稳定且不重复，例如 `my_fixed_camera`
- `title_zh`：节点和诊断中显示的中文名
- `scope`：`全部`、`T2VA`、`I2VA`、`FL2VA`、`L2VA`、`Ref2VA`，多个用英文逗号分隔
- `features`：便于检索的简短标签
- `instructions`：只写这一条规则负责的目标、保留项与禁用项

简单模板不声明互斥语义，始终可以被智能组合加载。确认规则边界后，再复制 `templates/用户高级创作规则模板.example.json` 增加：

- `semantic_contract`：稳定语义摘要；新规则使用 `purpose/adds/preserves/forbids/defaults`，不写某家 API 或模型的专属措辞
- `ownership`：规则读取、主导或补充哪些语义域
- `resolution`：依赖、冲突、互斥组和优先级

同一互斥组只会保留一个主规则。优先级高者胜出；同优先级时，前面的规则槽或规则包顺序优先。规则 `id` 重复时，已选择的内置规则优先于外部规则包。

如果规则来自官方/社区 Skill、Agent 工作流或较长的研究文档，不要直接缩写全文。先阅读 `docs/从Skill到创作规则模块.md`，复制 `templates/Skill转规则模块工作单.example.md`，把内容分成“保留为一次提示词语义 / 转成元数据 / 路由到其他层 / 删除”四类。插件内置模块的整体重写顺序和验收门槛见 `docs/提示词模块重写路线图.md`。

## 写作边界

- 一个规则只解决一类问题，例如身份、主运镜、对白或循环，不重复核心三段式/六段式格式。
- 规则只说明素材的职责与需要保留的可见事实，不自行分配 `<Picture N>`、`<Video N>`、`<Subject N>`、音频或说话人编号；真实标签和编号由 Media Registry/Protocol 根据当前连线生成。
- 不把本地文件路径、个人素材名或只对一次工作流成立的素材内容写进可复用规则。
- 不在规则中保存 API Key、Base URL、私人路径或个人素材名。
- JSON 字符串内换行使用 `\n`，不能直接插入裸换行。
- 先用一条规则和固定样本做 A/B，再决定是否加入依赖、冲突和更高优先级。

直载诊断只说明文件是否成功读取；智能组合的预览、诊断和 manifest 才是“最终有哪些规则真正发送给提示词模型”的依据。
