# MiniMax H3 短视频回归测试矩阵

测试目的不是一次生成“最惊艳的视频”，而是让每次节点或模块修改只验证一个可归因的能力。建议先固定：0.4 MP、5 秒、24 步、同一种子、缓存关闭；基线通过后再单独打开缓存做速度/质量 A/B。

## 最小 6 例

| ID | 模式 | 只测什么 | 推荐模块 | 通过标准 |
|---|---|---|---|---|
| T01 | T2VA | 三字段、单镜、声音 | 单镜连续性 | 只有一个清楚动作；无无故切镜；声音来源合理 |
| T02 | I2VA | 第 0 帧硬锚定 | 静态锚定·细微动态 | 视频第 1 帧与输入首图构图一致；只发生指定微动 |
| T03 | FL2VA | 首尾关键帧 | 无额外模块 | 起点/终点分别对齐两张图；中间过渡连续 |
| T04 | Ref2VA | 背景图 + 人物身份图 | 多参考图分镜映射、动漫角色身份保持 | 人物身份来自图 2，空间构图参考图 1；不能把“首帧完全一致”列为硬通过项 |
| T05 | Ref2VA | 双人空间与身份 | 双人互动 | 两人不交换、不融合；站位、视线和接触点连续 |
| T06 | T2VA/Ref2VA | 一句对白与原生音频 | 对白表演与口型 | 原文不被改写；只有说话者开口；声音/口型时机大致一致 |

可选扩展：产品包装一致性、UI 原文、参考视频动作迁移、视频配套原声、3/5/9 图压力测试。扩展项应在前六例稳定之后进行。

## A/B 纪律

每轮只改变一个变量：模块、缓存阈值、参考图尺寸策略或提示词中的一句话。记录 seed、模式、模型、分辨率、帧数、步数、缓存参数、生成耗时和输出文件名。不同模型权重（FL2VA 与 Ref2VA）的结果只能比较任务特性，不能当成严格的同模型 A/B。

评分建议每项 0–2 分：

- 输入/参考遵守；
- 身份与结构连续性；
- 动作和镜头可读性；
- 声音与事件同步；
- 明显伪影；
- 主观观感。

前五项用于判断节点是否退化，最后一项才是“好不好看”。这样即使随机性导致某次不够惊艳，也能判断模块逻辑是否正确。

## T02 与 T04 必须成对保留

用同一张场景图分别测试：

- T02 把图接到 `ImageToVideo.first_frame`：检查硬首帧是否成立；
- T04 把图接到 `ReferenceToVideo.ref_image`：观察软参考会怎样重构。

这组对照能长期防止把 Ref2VA 的 `<Picture 1>` 误解成首帧接口，也是本次 `00057` 异常最直接的回归样例。
