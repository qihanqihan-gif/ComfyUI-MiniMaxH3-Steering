# 提示词模块重写路线图

> 适用于 MiniMaxH3-Lab 的 33 个内置 JSON。当前目录结构与加载器已经完成迁移；本文只规划模块内容与语义契约的重写，不改变稳定模块 `id`，也不把供应商专属提示词复制成多套业务逻辑。

## 当前基线

33 个内置 JSON 分为：

| 类别 | 数量 | 处理方式 |
|---|---:|---|
| 自动核心协议 | 2 | 与官方 `h3-prompt-writing` 对齐；不可由用户选择 |
| 旧版兼容定义 | 4 | 隐藏、只为旧工作流保留，不继续扩写 |
| 参考 / 身份 / 任务规则 | 5 | 重写为明确的语义所有权和素材职责 |
| 对白 / 文字规则 | 2 | 只保留创作策略；精确格式归核心协议与编译器 |
| 镜头 / 动作 / 连续性规则 | 8 | 建立单一主职责、互斥组与冲突关系 |
| 通用增强规则 | 4 | 3 个保留为原子可选规则；1 个降为不可注入的作者参考资料 |
| 场景配方 | 8 | 从官方场景 Skill 中只提取“一次 H3 提示词调用需要的语义” |

前一轮已经完成 `prompt_modules/builtin/` 中文正式库、旧路径映射、结构化规则包、基础 ownership/resolution 和确定性冲突消解。第二批又将 `community_8_tips` 降为作者参考资料，因此当前为 26 个可选规则；这不代表其余规则正文已经完成同一标准的重写。

## 重写原则

1. **先写语义契约，再写 instructions。** instructions 是契约的当前渲染结果，不是唯一事实来源。
2. **一个模块只主导一个问题。** 允许补充多个正交字段，但只能有清楚的主要 `writes` 语义域。
3. **协议、节点参数和创作策略分离。** 字段顺序、标签语法、时间码格式属于 Protocol/Compiler；时长、比例、帧数属于节点；模块只描述创作策略。
4. **Skill 不等于模块。** Skill 中的提问、选择卡、浏览、下载、资产生成、审批、模型选择、调用、等待、剪辑和交付流程不进入模块。
5. **不做“每个模型一整套 instructions”。** 先保留一份 canonical contract。未来的 compact/standard/strong 只是同一语义的不同表达复杂度；供应商差异只有重复回归失败后才允许小型 patch。
6. **负面要求先成为 `forbids` 语义。** 只有和当前任务风险相关时才渲染成少量自然语言限制，不默认堆固定负面尾巴。
7. **来源和结论分级。** 官方协议、官方场景 Skill 改编、社区经验和项目实验必须保持不同 `evidence_level`。

## 重写批次

### 第 0 批：协议与兼容层

- `protocol_base`、`protocol_ref`：只同步官方字段、标签、声音和模式规则；不吸收场景风格、模型推荐或社区技巧。
- `official_three_part`、`official_six_part`、`dialogue_verbatim`、`shot_timeline`：继续隐藏，只保留迁移说明，不再优化正文。

验收：五种任务模式都由正确协议自动加载；旧定义不能出现在可选列表或被文件直载器注入。

### 第 1 批：高风险任务、素材路由与主镜头

优先处理：

- `character_replacement`
- `storyboard_reference_map`
- `single_shot_continuity`
- `natural_camera_follow`
- `slow_push_in`
- `subtle_still_motion`

这 6 个模块已于 2026-08-30 完成 canonical contract、ownership、resolution 与 instructions 的第一轮重写：

| 模块 | 主写入语义 | 组合结果 |
|---|---|---|
| `character_replacement` | `task.intent`、`identity.policy.primary` | 背景、镜头、剪辑和时间线只进入 preserves；可与循环策略组合 |
| `storyboard_reference_map` | `shot_plan.reference_mapping`、`timeline.layout.primary` | 与单镜连续性互斥；只使用已连接物理素材标签 |
| `single_shot_continuity` | `timeline.layout.primary` | 与多分镜映射互斥；可接受独立主运镜规则 |
| `natural_camera_follow` | `camera.motion.primary` | 与缓慢推进二选一；可叠加细微动态 |
| `slow_push_in` | `camera.motion.primary` | 与自然跟随二选一；不再自动替主体添加微动作 |
| `subtle_still_motion` | `motion.micro` | 不占主运镜；无主运镜时才默认固定机位 |

自动化回归已经验证以下边界；固定视频 A/B 仍待按同素材、同参数执行：

- 人物替换只能替换身份，不能顺手重写背景、镜头或时间结构。
- `<Subject N>` 与物理 `<Picture N>` 的职责不能混淆。
- 多镜映射和单镜连续必须由 Resolver 二选一。
- `static`、`tracking`、`slow push-in` 只能有一个主运镜所有者。
- 微动态属于动作增量，不应自动取得主运镜所有权。

实现状态：JSON/Resolver/文件直载回归已通过；尚不把本批标记为“视频效果定论”。

### 第 2 批：通用增强瘦身

本批已于 2026-08-30 完成第一轮落地：

| 模块 | 处理结果 | 主写入语义 |
|---|---|---|
| `community_8_tips` | `selectable:false`；保留来源和稳定 id，迁移为 `docs/创作规则作者检查清单.md` | 无，不参与运行时注入 |
| `cinematic_realism` | 只保留画面媒介、物理光线、材质与摄影层次 | `visual.medium.primary`、`visual.lighting.primary` |
| `negative_guidance` | 改为按风险产生最多 3 条 semantic exclusions，不暗示独立负面通道 | `constraints.semantic_exclusions` |
| `weather_ambience` | 只负责一种主导天气及其表面、能见度、光线和声音响应 | `environment.weather.primary` |

三条可选规则互相正交，也不取得主运镜、身份或时间结构所有权。`community_8_tips` 的只读 legacy 副本由 ID 级迁移保护同时隐藏，不能通过文件直载或外部规则包重新注入。

### 第 3 批：8 个官方场景 Skill 配方

本批已于 2026-08-30 逐个回到官方 Skill 原文完成第一轮重写，不再润色旧浓缩文案：

| 模块 | 场景主配方 | 是否取得主视觉媒介 | 关键边界 |
|---|---|---|---|
| `scene_3d_animation` | 风格化 3D 单片段 | 是：`stylized_3d_animation` | 不模仿具体工作室/渲染器；不接管主运镜和时间线 |
| `scene_brand_promo` | 单焦点品牌宣传 | 否 | 只使用已验证资产、事实和逐字文案；可与写实电影感组合 |
| `scene_coop_game_intro` | 双人主菜单开场 | 否 | 两名玩家身份/名字/屏幕区域不互换；只保留一个 UI 状态 |
| `scene_handdrawn_live` | 手绘实体与实拍接触/变形 | 是：`rough_handdrawn_animation_over_live_action` | 同一实体、真实接触、连续空间；延迟跟拍只是无主运镜时的默认值 |
| `scene_minimalist_product_ad` | 单产品单卖点极简广告 | 否 | 排除 T2VA；必须有已连接产品参考；同屏至多一行用户文案 |
| `scene_mv_subtitle` | 当前短片的歌词空间排版 | 否 | 歌词逐字保留；无音频参考不声称逐拍同步；可与屏幕文字规则组合 |
| `scene_paper_collage` | 扁平分层编辑式纸拼贴 | 是：`layered_halftone_paper_collage` | 纸片装配承担节奏；默认无旁白/BGM/字幕 |
| `scene_papercraft_stopmotion` | 有厚度的纸艺微缩定格 | 是：`handmade_multiplane_papercraft_diorama` | 必须有纸机构、厚度和多平面深度，不能只是纸纹贴图 |

8 个配方统一写入 `scene.recipe.primary`，因此同一轮只保留一个场景主配方；同优先级时按用户槽位顺序确定。四个固定视觉媒介的配方还加入 `visual.medium.primary` 互斥组，会与写实电影感自动二选一。品牌、游戏开场、极简产品广告和 MV 字幕不强制画风，因此仍能与独立视觉增强组合。

最终规则只保留画面风格、身份/产品保留、当前短片内部节拍、可见文字、声音策略和关键失败边界；官方 Skill 中的提问卡、浏览、资产准备、模型路由、逐镜调度、审批、拼接和交付流程均未进入运行时 `instructions`。所有模块使用显式任务模式列表；极简产品广告因官方要求至少一张产品图，收紧为 `I2VA/FL2VA/L2VA/Ref2VA`。

### 第 4 批：其余原子规则

本批已于 2026-08-30 完成第一轮 canonical contract、ownership、resolution 与 instructions 重写：

| 模块 | 主写入语义 | 组合 / 冲突结果 |
|---|---|---|
| `anime_identity` | `identity.character.reference_fidelity` | 只读已连接角色参考；可与人物替换组合，不锁死参考图姿势/表情 |
| `product_identity_fidelity` | `identity.product.reference_fidelity` | 只读已连接产品参考；可与品牌宣传、极简产品广告和写实电影感组合 |
| `two_person_interaction` | `interaction.blocking.primary` | 只负责站位、视线、路径与接触顺序；可与身份、对白和运镜规则组合 |
| `dialogue_performance` | `audio.dialogue.performance.primary` | 只负责逐字对白的发声表演；说话人编号和字段位置交给核心协议 |
| `ui_screen_text` | `visible_text.policy.primary` | 只负责用户可见文字、层级和时机；可与 MV 字幕及对白规则组合 |
| `motion_emphasis` | `motion.action.primary` | 不取得主运镜；与静态微动和动态壁纸冲突，可与跟拍/环绕等运镜组合 |
| `parallax_motion` | `camera.motion.primary` | 与缓慢推进/自然跟随互斥；仅适用有可靠深度证据的 I2VA/L2VA/Ref2VA |
| `seamless_loop` | `timeline.loop.primary` | 与多分镜映射和单向缓慢推进冲突；可与人物替换、身份和动作规则组合 |
| `live_wallpaper` | `presentation.wallpaper.primary`、`timeline.loop.primary` | 比通用循环更具体且优先；与动作强化、多分镜映射、单向推进冲突 |

本批同时删除了原子规则中的协议重复：身份规则不再硬编码 `<Subject N>/<Picture N>`，对白、互动与字幕规则不再自行分配 `(S1)/(S2)` 或规定字段位置。它们只声明素材职责、逐字保真和表演语义，实际标签、编号与输出格式继续由 Protocol、Media Registry 和 Compiler 统一处理。

自动化回归已经覆盖参考素材缺失、scope 不匹配、互斥主运镜、动作与静态模板冲突、动态壁纸取代通用循环，以及身份/互动/对白/文字的正常组合。固定视频 A/B 仍属于第 5 批，不以单个成功样本升级通用结论。

### 第 5 批：渲染分档与模型实测

只有 canonical contract 稳定后才做：

1. 用固定回归集比较 compact / standard / strong 三档表达。
2. 记录模型、provider、wire、上下文、素材清单、模块版本和请求指纹。
3. 只有同一模型在多个 fixture 中稳定出现同一失败，且通用 strong 档无法修复时，才增加窄范围 measured override。

在这一步之前，模块不得标注“某模型最佳”“某供应商专用”或“官方推荐档位”。

2026-08-30 已完成本批的**可复现实验地基**，尚未形成模型质量结论：

- `standard`：原样使用当前 `instructions`，也是旧工作流与新节点的默认档；默认行为不变。
- `compact`：只从 canonical contract 与 ownership 确定性渲染目标、主职责及每类前两个关键保留/禁用边界；它是低显式度实验档，不调用模型改写。
- `strong`：保留当前 `instructions`，再附同一 canonical contract 的复核文本；用于验证较弱模型是否需要更显式约束。
- `module_manifest` 升为 `h3_prompt_modules/1.2`，记录渲染档、每个模块版本/渲染来源/文本哈希、模块集合哈希及最终规则文本哈希；导演报告会回显这些非秘密指纹。
- 独立文件直载器继续输出原始 `instructions`，可作为不经过 Resolver 和渲染分档的对照基线。
- 实验记录使用 `templates/模块渲染A-B实验记录.example.md`；每轮只改变渲染档，避免把模型、素材、seed 或节点参数变化误归因给模块。

上述三档只是 A/B 工具，不代表 `compact` 更快或 `strong` 更好。下一步仍需用固定 fixture、同素材、同参数和成对种子实测；在至少多个 fixture 重复出现同一失败前，不增加供应商专属 override。

## 单模块完成标准

每个可选模块完成重写时必须同时满足：

- `id` 稳定且唯一，中文文件名和 `title_zh` 对齐。
- 一句话能说清模块目的和不适用场景。
- `semantic_contract` 至少明确 `purpose`，并按需要给出 `adds`、`preserves`、`forbids`、`defaults`。
- `ownership.writes` 只有必要的主要语义域；补充项进入 `augments`。
- `resolution` 的依赖、成对冲突、互斥组和优先级与 ownership 一致。
- instructions 由 contract 派生，目标长度约 180–600 个中文字符；复杂任务可超出，但必须说明原因。
- 不包含 API、Agent、画布、审批、下载、剪辑、模型选择或供应商连接流程。
- 不重复自动协议，不虚构未连接素材，不改写用户逐字文字/对白。
- 至少有 1 个正常样本、1 个不适用样本、1 个冲突样本和 1 个素材缺失样本。

## 验证顺序

1. JSON/schema 与元数据检查。
2. Resolver 单元测试：作用域、依赖、冲突、互斥组、稳定顺序。
3. Prompt IR 测试：规则是否进入正确字段，是否污染无关字段。
4. Protocol/Compiler 测试：最终格式、标签、时间码、对白和声音字段。
5. 固定视频生成 A/B：同素材、同参数、成对种子，只改变模块或渲染档。

先完成第 1–4 项才值得消耗云端 API 或本地长时间生成；单个成功视频只能形成实验线索，不能升级为通用规则。
