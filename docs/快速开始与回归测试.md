# 快速开始与回归测试

> 目标：先发现安装、交互、接线、兼容和规则组合问题，再讨论模型质量。测试者不需要证明所有模块有效，也不要因一次成功或失败修改通用规则。

## 一、加载本批更新

1. 等当前任务全部结束后，完整退出并重新启动 ComfyUI。
2. 浏览器执行 `Ctrl+F5`，避免继续使用旧前端脚本。
3. 打开“MiniMax H3 创作规则组合”节点，确认底部出现“规则渲染档（A/B 实验）”。
4. 默认必须是 `standard`。若没有新控件，先确认当前启动的是 WF 环境，再检查浏览器缓存和 ComfyUI 启动日志。

## 二、保护现有工作流

- 先把当前视频替换工作流另存为测试副本，不在常用版本上直接实验。
- 不移动或重接现有参考图、参考视频和 H3 conditioning 线路；先截图保存关键接线。
- 固定提示词模型、provider、wire、模型 ID、上传方式、参考图、参考视频、自然语言意图和模块组合。
- 固定 H3 模型、分辨率、时长、FPS、steps、seed 与其它采样参数；关闭或固定可能改变结果的缓存策略。
- 每轮只改变 `render_profile`，否则只能算观察，不能算严格 A/B。

## 三、第一组样本：现有视频替换工作流

第一轮只选择：

- 作用域：`Ref2VA`
- 规则 1：`人物替换（Ref2VA 换人复刻）`
- 其它可选规则：先设为“无”
- 渲染档：从 `standard` 开始

自然语言意图尽量简单，可沿用现有文本；若需要干净基线，可使用：

```text
用已连接参考图中的目标角色替换参考视频里的原人物。只替换人物身份；保持原视频的背景、构图、灯光、运镜、动作、节奏、剪辑和时间顺序不变，让目标角色执行原人物的表演。
```

不要在三档之间继续改写这段文字。

## 四、先做提示词层烟雾测试

在消耗视频生成时间前，先只检查提示词链：

1. 保留导演节点的文本、报告、参考分析表和 Prompt IR 显示节点。
2. 暂时旁路/静音最终 H3 视频生成分支，或复制一个只输出文本报告的测试工作流。
3. 分别运行 `standard`、`compact`、`strong`。
4. 每档记录：
   - 最终增强提示词。
   - Prompt IR。
   - 规则解析清单中的 `render_profile`。
   - `module_set_sha256`。
   - `rendered_system_sha256`。
   - 导演报告中的请求指纹。
5. 同一档重复一次时，模块集合与规则文本哈希应一致；三档之间规则文本哈希应不同。

先检查三档是否都仍然表达“只替换人物身份，保留原视频其它结构”。若某档已经在提示词层写成续写、整段重绘或背景重构，不必继续生成视频，先保存报告反馈。

## 五、再做真实视频 A/B

建议先生成 `standard` 与 `compact`；只有提示词层确实显示强化差异时，再生成 `strong`，节省时间。

文件名建议：

```text
replace01_standard_seed1234.mp4
replace01_compact_seed1234.mp4
replace01_strong_seed1234.mp4
```

若第一组差异明显，再换第二个 seed 重复；不要立刻换素材或模型。

视频检查项：

1. 原人物身份是否被移除，而不是与目标角色混合。
2. 目标角色脸、发型轮廓、服装版型和关键配色是否连续。
3. 原视频动作、手势、表情时点和空间路径是否被转移。
4. 背景、构图、灯光、运镜、剪辑和时间顺序是否保持。
5. 是否出现整段重绘、场景替换、视频续写或事件重排。
6. 是否把参考图中的静态姿势、表情或构图错误锁到全片。

使用 `templates/模块渲染A-B实验记录.example.md` 保存结果。

## 六、第二组样本：身份规则组合

第一组跑通后，保持素材与参数不变，只在新实验中增加：

- `动漫角色身份保持`

比较：

```text
人物替换
人物替换 + 动漫角色身份保持
```

这轮测试“身份模块是否提供正交增益”，不要同时比较渲染档；先固定为 `standard`。若组合确实减少身份漂移，再另开一轮比较三档。

## 七、怎样判断问题属于哪里

- **三档提示词都正确，但视频都失败**：优先检查 H3 生成能力、参考素材质量、conditioning 接线和采样参数，不先改模块。
- **三档都在提示词层犯同一个错误**：检查 canonical contract、自然语言意图或素材职责。
- **compact 稳定失败，standard/strong 稳定成功**：说明该提示词模型可能需要更显式规则；至少换第二个 seed，并在多个 fixture 重复后再形成结论。
- **只有 strong 偶尔成功**：先视为随机观察，不创建供应商专属 override。
- **同一档重复运行时 Prompt IR 差异很大**：记录提示词模型温度、思考模式和 provider；先解决上游不稳定，再比较 H3 视频。
- **规则解析清单显示模块被 suppressed**：先读 winner/reason，不把未实际应用的模块当成模型质量问题。
- **页面明显卡顿**：记录工作流节点数、打开的标签页、是否存在大量图像预览；规则渲染节点本身不加载缩略图或展开视频帧。

## 八、问题反馈最少需要提供

- 插件测试包版本与 ComfyUI 版本。
- 操作系统、Python/CUDA 的大致版本。
- 使用的节点和渲染档。
- 最小可复现工作流（先确认不含凭据）。
- 报错截图、ComfyUI 日志中的错误类型和节点报告。
- 是否能稳定复现，以及复现步骤。
- 若是质量问题：使用的 fixture、seed、模块组合和三档指纹。

不要发送 API Key、Authorization header、凭据文件、完整用户目录、私人绝对路径或未经确认可分享的原始素材。
