# 关键结论与当前状态

> 用途：给新会话、维护者和测试者提供一个不依赖聊天上下文的入口。若本文与旧交接记录冲突，以当前代码、自动化测试和本文指向的专题文档为准。
>
> 最近核验：2026-09-01；当前主源码全量 `234 passed`，Python/JSON/前端静态检查通过。此前 26/WF 部署副本的 `233 passed` 属于目录统一前版本；本轮目录整理尚未重新部署。

## 一、稳定架构结论

1. **LLM 负责内容规划，Python 负责协议编译。** 三段式/六段式、字段顺序、时间码、素材标签、对白与声音字段属于 Protocol/Compiler，不由创作规则各自重复实现。
2. **素材真实连接与编号属于 Media Registry。** 创作规则只声明素材职责与需保留的可见事实，不自行分配 Picture、Video、Audio、Subject 或说话人编号，不虚构未连接素材。
3. **先有 canonical semantic contract，再有 instructions。** `instructions` 是当前渲染文本；事实源是 `purpose/adds/preserves/forbids/defaults`、`ownership` 与 `resolution`。
4. **一个模块只主导一个主要问题。** 作用域、依赖、冲突、互斥组和优先级由确定性 Resolver 在调用 LLM 前处理；同一输入必须得到同一解析结果。
5. **Skill 不等于运行时模块。** Skill 中的提问、工具、浏览、下载、资产生成、模型路由、审批、等待、剪辑和交付流程不能直接进入一次 Prompt Director 调用。
6. **不维护每个模型一整套业务提示词。** `compact/standard/strong` 只表达同一契约的不同显式程度；只有固定回归反复证明通用强化仍失败时，才允许增加窄范围 measured override。

专题依据：`H3-Prompt-IR与编译器.md`、`从Skill到创作规则模块.md`、`提示词模块重写路线图.md`。

## 二、创作规则当前状态

- 规则统一入口：`prompt_modules/`，不再在插件根目录平铺三个相近目录。
- 正式内置库：`prompt_modules/builtin/`，真实中文文件名；稳定 `id` 保持英文小写下划线。
- 个人规则：`prompt_modules/user/<自定义目录>/`；该目录的用户内容默认被 Git 忽略。
- 旧版兼容库：`prompt_modules/legacy/`；旧英文选择值按稳定 `id` 映射到中文正式文件，不在这里新增规则。
- 当前有 26 个可选规则、2 个自动核心协议、4 个隐藏兼容定义和 1 个只读作者参考条目。
- 第 0～4 批已完成第一轮 contract、ownership、resolution、instructions 与自动化回归；这表示结构与组合边界通过，不表示所有视频效果已经形成统计结论。
- 第 5 批已提供三个可复现实验档：
  - `standard`：原样使用当前正文，默认且兼容旧行为。
  - `compact`：只从 canonical contract 与 ownership 生成目标、主职责和关键保留/禁用摘要。
  - `strong`：当前正文加同一契约复核。
- `module_manifest` v1.2 记录渲染档、模块版本、渲染来源、每模块文本哈希、模块集合哈希和最终规则文本哈希；导演报告回显这些非秘密指纹。
- 上述档位是 A/B 工具，不是质量排名；没有实测前不得写“某模型最佳”“某供应商专用”或“官方推荐档位”。

## 三、自定义规则与 AI 作者边界

用户材料可以是自然语言需求、参考案例、研究记录、已有提示词、素材说明或一份完整 Skill。AI 不应直接复制或压缩全文，而应先做四向分拣：

1. 保留为一次提示词调用需要的可复用创作语义。
2. 转成 `semantic_contract / ownership / resolution / evidence_level` 元数据。
3. 把协议、素材编号、节点参数、连接、验证与工具流程路由到对应层。
4. 删除只对原 Agent 工作流成立的审批、等待、下载、剪辑与交付步骤。

最终产物是插件读取的 JSON；指导 AI 完成“材料盘点 → 证据分级 → 四向分拣 → 契约 → JSON → 校验 → A/B”的完整工作流，才是独立的**模块作者 Skill**。当前已有转换指南、检查清单、工作单、Skill 设计和回归测试指南；实际可安装 Skill 与自动校验入口仍待后续打包。

## 四、API Key 与云端连接结论

- 节点不提供会被序列化进工作流的 API Key 输入框。
- Key 只从环境变量或 ComfyUI 用户目录下的本地凭据文件解析；保存连接与凭据使用稳定引用，工作流、普通报告和节点输出不保存明文 Key。
- 内置 provider 与 OpenAI-compatible 连接分层处理；provider、wire、capability 与业务提示词不混成一套条件分支。
- 网络重试保持同一请求体；JSON/Prompt IR 修复属于新请求并产生新 fingerprint。
- 连接、模型列表和视觉探针的结果只能证明对应接口行为，不能自动证明完整 H3 提示词质量。

详细实现与安全说明以 `README.md` 的云端连接、凭据与诊断章节为准。

## 五、参考图、视频与时间线结论

- 提示词导演接收的参考图/视频只发送给提示词模型，不会自动成为 H3 生成节点的视觉条件；用户仍需把素材连接到官方 H3 节点。
- 素材引用弹窗是接线与官方标签之间的防错层，不是质量增强器；它不加载缩略图、不展开数百帧、不后台轮询，也不改写用户提示词。
- DeepSeek 的 600 帧只是受控能力边界实验：控件上限不等于实际必然发送 600 帧，报告中的实际帧数、载荷和请求指纹才是证据。
- Gemini 支持抽帧与原生视频两条互斥路径；原生视频不解码成数百张前端预览，Files API 临时文件在调用结束后尽力清理。
- 视频时间线 manifest 只提供确定性源帧索引、时间码、相对位置与切镜分段，不承担复杂剪辑工作台或语义推断。
