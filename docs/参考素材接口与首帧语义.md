# MiniMax H3 参考素材接口与首帧语义

本文对应 ComfyUI 官方 `MiniMaxH3ImageToVideo` 与 `MiniMaxH3ReferenceToVideo`。结论来自当前官方节点实现，而不是根据端口在画布上的视觉位置猜测。

## 一眼判断该用哪个节点

| 目标 | 官方节点 / 模型 | 图像语义 | 能否硬锁第 0 帧 |
|---|---|---|---|
| 文生、首帧、首尾帧、尾帧 | `MiniMaxH3ImageToVideo` / FL2VA 权重 | `first_frame` 与 `last_frame` 是生成关键帧 | 是 |
| 多图、多视频、音频参考 | `MiniMaxH3ReferenceToVideo` / Ref2VA 权重 | 所有 `ref_image` 都是通用 `<Picture i>` 条件 | 否；只能通过 prompt 做软锚定 |

如果要求“完整保留这张图作为视频开头”，应把它连接到 `first_frame`。如果还要使用另一张人物立绘，最稳的方法是先把人物和场景合成一张正确的首帧，再走 ImageToVideo；Ref2VA 可以混合多个参考，但不能把任意 `ref_image` 变成与 `first_frame` 等价的 latent 锚点。

## 为什么“最上面的参考图效果差”不成立

`ref_image_*` 来自同一个 Autogrow 动态数组。官方执行代码按已提交的字典顺序遍历非空图片，做同一套缩放、VAE 编码和 DiT reference block 构造。端口在节点中的上下位置只反映用户添加动态端口的先后，**没有不同的权重、层级或算法**。

图片标签按实际进入 presentation 的顺序密集编号为 `<Picture 1>、<Picture 2>…`。若断开前面的端口，只保留后面的动态端口，视觉端口号不一定等于最终提示词编号。因此提示词导演也按已连接素材重新密集编号；正式运行前应查看诊断报告。

## 四类参考输入的顺序

官方 presentation 固定为：

1. 所有参考图；
2. 所有参考视频；某视频若带配套原声，其 `<Audio j>` 会在该 `<Video k>` 前插入；
3. 所有独立参考音频。

类型内部按实际输入顺序编号，Picture / Video / Audio 各有独立编号空间。视频端口与同后缀的原声端口配对，例如 `ref_video_1` 对应 `ref_video_audio_1`。由于 Audio 编号还会受到前面已连接的视频原声数量影响，不能只凭音频端口的视觉序号猜 `<Audio j>`。

| 类型 | 官方动态端口上限 | 实际处理 |
|---|---:|---|
| 参考图 | 9 | 每个端口只取批次第 1 张；`match` 或 `max` 后编码 |
| 参考视频 | 3 | 官方提示 2–15 秒；代码至少要求 5 帧，先截到生成帧数，再从尾部对齐到 `17k+5` |
| 视频配套原声 | 3 | 与同编号参考视频绑定；没有对应视频时不形成视频配套引用 |
| 独立参考音频 | 3 | 重采样到 Audio VAE 采样率后编码 |

参考视频的 VAE 路径按 24 FPS 使用对齐后的完整帧；Qwen 视觉 presentation 每 12 帧取一张，即按 2 FPS 带时间戳观察。生成长度的官方训练提示范围约 124–362 帧（约 5–15 秒），更长虽未被节点硬禁止，但属于未验证范围。

## `match` 与 `max`

- `match`：保持宽高比，只向下缩到不超过生成画面的总像素面积，然后宽高分别取 32 倍数。通常速度和内存更友好。
- `max`：保持宽高比，短边大于 2048 时才向下缩；小图不主动放大。参考 token 会贯穿每个采样步，长边很大的竖图可能比 `match` 慢数倍。

二者都不裁剪参考图，也都不会把参考图变成生成首帧。它们只改变参考条件的分辨率与成本。

## 首帧与尾帧的几何处理

- `first_frame`：官方代码直接拉伸到目标宽高并写入第 0 帧 latent。
- `last_frame`：保持宽高比做居中 cover-crop，再写入最后一帧 latent。

因此纵向首图直接送入横向生成画布会被明显拉伸。要“完整保留、不裁剪、也不变形”，先用本插件 `MiniMaxH3ReferenceMediaPrep` 的 `contain_pad` 处理到目标画布，再接 `first_frame`。

## 当前工作流异常的复盘

`MiniMax_H3_00057_.mp4` 的嵌入工作流显示：

- 下游使用 `MiniMaxH3ReferenceToVideo` 和 Ref2VA 权重；
- 两张图都接到 `ref_images`；
- PromptDirector 却选择 `I2VA`，模块节点作用域选择 `Ref2VA`；
- 输出语言为中文，因此官方英文协议没有自动注入。

这两张图从未进入 `first_frame`，所以“图 1 作为底图”只是文本愿望。成片首帧更接近第二张透明人物立绘并重构背景，符合 Ref2VA 的参考混合行为，不是首图缩放节点失效。

修复路线二选一：

1. **硬首帧**：FL2VA 权重 + `MiniMaxH3ImageToVideo.first_frame`，PromptDirector 选 I2VA、English；需要额外人物信息时先合成正确首帧。
2. **多参考混合**：Ref2VA 权重 + `MiniMaxH3ReferenceToVideo`，PromptDirector 和模块作用域都选 Ref2VA、English；使用“多参考图分镜映射”模块，并把第一张图视作软 `<Picture 1>` 构图锚点，而不是硬底图。
