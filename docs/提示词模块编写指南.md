# 提示词模块编写指南 · 官方 Skill → 模块转换方法

> 2026-08-07 · MiniMax-H3-Lab v0.1
> 配套：`Codex/ComfyUI-MiniMaxH3-Lab/modules/*.json`（16 个模块）

## 一、模块到底是什么（一句话）

**模块 = 可选的「创作策略包」**——它只负责告诉 LLM「这次视频的创作侧重点」（风格/场景/题材），不负责格式（格式是核心协议自动加载的）。

模块节点输出一段 system 文本，接到 PromptDirector 的「提示词模块」输入，与核心协议、内置模板合并后一起发给 LLM。

## 二、JSON 格式规范

```json
{
  "id": "motion_emphasis",
  "title_zh": "动作强化",
  "version": 1,
  "scope": "全部",
  "source": "官方 skill: xxx / 社区 xxx / 自研",
  "instructions": "创作策略：……\n1. ……\n2. ……"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一英文标识（小写+下划线），用于诊断显示 |
| `title_zh` | ✅ | 中文名，显示在节点下拉框 |
| `version` | 建议 | 整型，版本管理 |
| `scope` | ✅ | 适用模式：`全部` / `T2VA` / `I2VA` / `FL2VA` / `Ref2VA`（多个用逗号：`T2VA,I2VA`） |
| `source` | 建议 | 内容来源（可溯源卖点） |
| `instructions` | ✅ | 策略指令正文 |

⚠️ **JSON 里不能用裸换行**：`instructions` 内的换行必须写成 `\n`（一行一个 JSON 字符串）。写错会导致整个模块加载失败（日志会报 Invalid control character）。

## 三、模块文件放哪、怎么生效

- 位置：`Codex/ComfyUI-MiniMaxH3-Lab/modules/*.json`
- **热加载**：放进去/改完保存，节点下拉框和输出自动刷新（无需重启 ComfyUI；执行时会重新读盘）
- 下拉框显示格式：`title_zh（v版本号）`；模块节点最多同时选 3 个 + 1 个自定义规则框

## 四、官方 Skill → 模块的转换方法（核心流程）

1. **读 SKILL.md 的 frontmatter `description`**：那是官方自己写的定位摘要（适用场景/产出/禁用场景）
2. **抽「视觉风格锁定」段**：凡出现 "style lock / rendering style / character design / negative style constraints" 的内容，是提示词层最值钱的部分——原样浓缩
3. **抽「创作原则」段**：Core principles / workflow 里与「怎么写提示词」相关的规则（节奏/结构/声音/排版），转成 1-2-3 条目
4. **抽负面约束**：`not / no / avoid` 开头的句子 → 负面约束条目（视频模型很吃负面约束）
5. **浓缩纪律**：instructions 控制在 1 屏（约 400-600 字），只保留「LLM 写提示词时必须知道的」，工作流/审批/画布类步骤一律丢掉
6. **标注 `source`**：官方 skill 名 / 社区来源 / GPT 5.6 核验，可溯源

## 七、写给想自己写模块的人

- 不会写提示词没关系：**先抄官方的**（上面的场景模块就是范本），改一两个词就是自己的模块
- 每个模块只解决一件事（「动作强化」里不写格式、「无缝循环」里不写对白语法）
- 写完用任意 JSON 校验器（或让节点跑一次看日志）确认无裸换行
- 模块越多 ≠ 越好：默认 3 槽，选 1-2 个最贴题的即可；核心协议永远自动兜底
