# 提示词模块编写指南

> 2026-08-30 · MiniMax-H3-Lab 模块 schema v1.1
> 配套：正式内置库 `prompt_modules/builtin/*.json`；用户库 `prompt_modules/user/<自定义目录>/*.json`；旧版最小 JSON 继续兼容
>
> 先读：`提示词模块重写路线图.md`；若来源是一份 Skill 或类似 Skill 的长文档，使用 `从Skill到创作规则模块.md` 与 `templates/Skill转规则模块工作单.example.md`；提交前再过一遍 `创作规则作者检查清单.md`。

## 一、模块到底是什么（一句话）

**模块 = 可选的「创作策略包」**——它只负责告诉 LLM「这次视频的创作侧重点」（风格/场景/题材），不负责格式（格式是核心协议自动加载的）。

规则组合节点先确定性处理作用域、依赖、冲突与互斥组，再把生效规则输出为 system 文本，接到 PromptDirector 的「创作规则」输入。被压制的规则不会发送给 LLM，并会记录在解析清单中。

## 二、JSON 格式规范

```json
{
  "id": "motion_emphasis",
  "title_zh": "动作强化",
  "version": 1,
  "scope": "全部",
  "category": "camera",
  "source": "官方 skill: xxx / 社区 xxx / 自研",
  "semantic_contract": {
    "purpose": "为当前任务指定唯一主运镜。",
    "adds": [{"path": "camera.motion.primary", "value": "tracking"}],
    "preserves": ["subject.identity"],
    "forbids": ["contradictory_primary_camera_motion"],
    "defaults": []
  },
  "ownership": {
    "writes": ["camera.motion.primary"],
    "augments": ["continuity.screen_direction"]
  },
  "resolution": {
    "exclusive_group": "camera.motion.primary",
    "priority": 50,
    "requires": [],
    "conflicts": []
  },
  "instructions": "创作策略：……\n1. ……\n2. ……"
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 唯一英文标识（小写+下划线），用于诊断显示 |
| `title_zh` | ✅ | 中文名，显示在节点下拉框 |
| `version` | 建议 | 整型，版本管理 |
| `scope` | ✅ | 适用模式：`全部` / `T2VA` / `I2VA` / `FL2VA` / `Ref2VA`（多个用逗号：`T2VA,I2VA`） |
| `source` | 建议 | 内容来源（可溯源卖点） |
| `semantic_contract` | v1.1 建议 | 与模型表达无关的稳定语义；新模块使用 `purpose/adds/preserves/forbids/defaults`，不写供应商专属提示词 |
| `ownership` | v1.1 建议 | `reads/writes/augments` 对应的语义路径；主规则用 `writes` |
| `resolution` | v1.1 建议 | `exclusive_group/priority/requires/conflicts`，由 Resolver 自动处理 |
| `instructions` | ✅ | 策略指令正文 |

⚠️ **JSON 里不能用裸换行**：`instructions` 内的换行必须写成 `\n`（一行一个 JSON 字符串）。写错会导致整个模块加载失败（日志会报 Invalid control character）。

## 三、模块文件放哪、怎么生效

- 内置位置：`ComfyUI-MiniMaxH3-Lab/prompt_modules/builtin/*.json`（随插件更新，不放个人规则）
- 用户位置：`ComfyUI-MiniMaxH3-Lab/prompt_modules/user/<自定义目录>/*.json`
- 兼容位置：`ComfyUI-MiniMaxH3-Lab/prompt_modules/legacy/*.json`（只读，不添加新规则）
- **热加载**：放进去/改完保存，节点下拉框和输出自动刷新（无需重启 ComfyUI；执行时会重新读盘）
- 规则组合节点最多同时选 5 个 + 1 个自定义规则框；同优先级冲突时，前面的规则槽优先
- 文件直载节点可一次选 5 个真实路径；它的文本输出不做冲突消解，第三个“结构化规则包”输出可接规则组合节点统一解析

第一次编写建议复制 `templates/用户简单创作规则模板.example.json`；需要依赖、互斥组和优先级时再使用高级模板。完整接线与字段取舍见《用户自定义创作规则.md》。

## 四、Skill 或长文档如何转换

不要把整份 `SKILL.md` 直接压缩成 `instructions`。Skill 往往同时包含触发、提问、工具、素材生成、模型选择、审批、剪辑和交付；创作规则模块只能保留**一次 Prompt Director 调用真正需要的语义**。

统一做四向分拣：

1. 最终画面、动作、镜头、声音和保真边界，写入 canonical `semantic_contract`。
2. 适用任务、职责、依赖和冲突，转成 `scope/ownership/resolution/evidence_level`。
3. 标签、字段顺序、时间码、素材编号、节点参数和连接逻辑，路由到 Protocol、Compiler、Media Registry、节点或连接管理。
4. 用户确认、画布、浏览、下载、模型调用、等待、审批、剪辑和交付步骤，从模块删除。

随后先审核 contract，再由 contract 写出简短 `instructions`；不能反过来把一段漂亮文案当事实源。完整步骤、官方 Skill 示例、证据等级与发布检查见 `docs/从Skill到创作规则模块.md`，提交前填写配套工作单。

## 五、现有模块清单

当前发布目录共 33 个 JSON：2 个自动协议、4 个仅供旧工作流兼容的隐藏别名、26 个可选创作规则，以及 1 个保留来源但不再注入的作者参考条目。下表保留早期基础范例；实际可选项以节点热加载列表为准。

**身份、互动、对白与文字原子规则（可选，5 个）**
| id | 中文名 | 要点 |
|---|---|---|

## 六、重写与转换入口

- 改写现有内置模块：按 `docs/提示词模块重写路线图.md` 的批次和单模块完成标准进行。
- 从官方/社区 Skill 新建模块：先复制 `templates/Skill转规则模块工作单.example.md`，再按 `docs/从Skill到创作规则模块.md` 分拣。
- 从零写一条个人规则：先复制简单 JSON；只有确实存在主语义所有权、依赖或冲突时才升级到高级 JSON。
- 不确定内容属于哪里：优先留在研究文档，不要为了“可选择”就硬塞进模块列表。

## 七、写给想自己写模块的人

- 不会写提示词没关系：先从简单模板写清“目标、保留、禁用”；不要复制整段官方 Skill 或只改几个词
- 每个模块只解决一件事（「动作强化」里不写格式、「无缝循环」里不写对白语法）
- 写完用任意 JSON 校验器（或让节点跑一次看日志）确认无裸换行
- 模块越多 ≠ 越好：默认 3 槽，选 1-2 个最贴题的即可；核心协议永远自动兜底
