# 创作规则作者检查清单

这份清单用于**编写或审查规则 JSON**，不会作为运行时规则注入 Prompt Director。旧模块 `community_8_tips` 曾把协议、格式、素材、镜头、声音、约束和长度建议合在一起，容易形成第二份总协议；其内容已经按职责拆回下列检查项。

## 八项检查

1. **单一职责**：一句话能否说明模块新增什么，以及它明确不负责什么？说不清时先拆分或保留为研究文档。
2. **用户意图优先**：模块不得翻译、润色或取消用户逐字文字、对白、核心动作与明确镜头要求。
3. **素材职责真实**：规则只能声明实际连接素材的职责和可见事实，不能虚构素材内容，也不能自行分配 Picture、Video、Audio、Subject 或说话人编号；真实标签与编号由 Media Registry/Protocol 负责。
4. **主所有者唯一**：主运镜、时间结构、身份策略、视觉媒介、天气等同一路径只能有一个 `writes` 所有者；补充项进入 `augments`。
5. **时间与因果可读**：模块可以规定创作节拍，但字段顺序、镜头标签、时间码格式与时长越界检查交给 Protocol/Compiler。
6. **声音来自可解释声源**：只补充当前任务真正需要的环境声、动作声、对白或配乐语义，不重复声音字段格式，不凭“电影感”自动加入音乐。
7. **约束由风险触发**：只写会阻止当前具体失败的少量 semantic exclusions；不附固定负面尾巴，不使用未定义控制标记，不让约束取消正向目标。
8. **复杂度服从任务**：简单单镜保持精炼；只有多人、多参考、多镜头或强叙事确实需要时才增加细节。模块正文目标约 180–600 个中文字符。

## 内容应该放到哪里

| 内容 | 负责层 |
|---|---|
| 三段式/六段式、字段顺序、标签语法 | Protocol |
| 时间码、首尾帧句式、格式修复 | Compiler |
| Picture/Video/Audio 的实际连接与编号 | Media Registry |
| 时长、比例、帧数、上传方式 | 节点输入与媒体层 |
| API、模型、thinking、重试、Key | Provider/连接管理 |
| 身份、动作、镜头、风格、天气等有限创作语义 | 创作规则模块 |
| 依赖、冲突、互斥和优先级 | Resolver metadata |

## 提交前最小检查

- 先填写 `templates/Skill转规则模块工作单.example.md`，或从简单/高级 JSON 模板开始。
- `semantic_contract` 使用 `purpose/adds/preserves/forbids/defaults`。
- `ownership.writes` 中的主路径应能在 `semantic_contract.adds[*].path` 中找到。
- 两个规则若写同一路径，应共享 `exclusive_group` 或声明明确冲突。
- 删除 `instructions` 后，contract 仍应能说明模块的真实意图。
- 至少覆盖正常、scope 不匹配、冲突、素材缺失和关闭模块五种回归情形。

更完整的来源分拣和 Skill 转换方法见 `docs/从Skill到创作规则模块.md`；内置模块的实施批次见 `docs/提示词模块重写路线图.md`。
